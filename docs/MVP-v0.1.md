# DevMeet MVP v0.1

작성일: 2026-10-07. 클로즈드 베타 제품 명세와 UI 구현 범위.

## 제품 정의

GitHub와 선택적 회사 이메일 인증으로 개발자 프로필의 신뢰를 높이고, 개발자와 개발자를 만나고 싶은 사람에게 매일 세 명을 소개하는 가치관 중심 소개팅 서비스.

핵심 경험: 인증으로 안심하고, 일상의 결로 선택하고, 서로 좋아할 때 대화한다. 개발자 화면에는 LGTM!(좋아요)·머지(매칭), 비개발자 화면에는 좋아요·매칭을 표시한다.

## 상충 요구사항 정리

| 항목          | v0.1 임시 기준                            | 해석                                  |
| ------------- | ----------------------------------------- | ------------------------------------- |
| 추천          | 무료 하루 3명                             | 한 줄 정의의 5명보다 상세 명세 우선   |
| 개발자 인증   | GitHub 필수, 회사 이메일 선택             | 상세 인증 명세 우선                   |
| 비개발자 인증 | 사진 검수, 회사 이메일 선택               | 휴대폰 인증은 제외 목록 우선          |
| 최종학력      | 고등학교·전문대·학사·석사·박사 졸업       | ‘곶’은 고등학교 졸업으로 해석         |
| 유료 필터     | 이번 버전 제외                            | 결제·구독 제외 방침 우선              |

회사 이메일이 선택이므로 모든 사용자에게 ‘현직 검증 완료’라고 표현하지 않는다. GitHub 소유 확인과 직무 검증은 다르므로 출시 전 검증 기준을 확정해야 한다. 위 항목은 기획 가정이다.

## 대상과 가설

주 타겟은 20–30대 직장인 개발자 남성과 개발자를 만나고 싶은 비개발자 여성. 학생은 서브 타겟이며 초기 베타는 서울·경기 27–35세에 집중한다.

검증할 가설은 개발자 소개팅 포지셔닝의 가입 효과, 인증 배지의 신뢰·좋아요 효과, 하루 3명의 선택 피로 감소, 기술 스택보다 가치관·생활 패턴의 대화 효과, 역할·성별 풀 구성비별 유효 매칭이다.

개발자는 개발자·비개발자·상관없음을 선택한다. 비개발자는 인증된 개발자를 추천받는다. 초기 추천은 이성이며 성별·나이·지역·활성 상태·사진 승인·상호 선호를 후보 조건으로 적용한다. GitHub 미연결 개발자는 추천 참여를 제한한다.

## 가입과 프로필

카카오 로그인 → 역할 선택 → 기본 정보 → 인증 → 가치관 → 사진 검수 → 추천 참여.

필수 정보는 이름, 나이, 성별, 사는 시·구, 직업, 최종학력, 키, 체형, 종교, 흡연, 음주, 얼굴 식별 가능한 사진, 자기소개와 하는 일이다. 직장·학교·키워드 최대 5개·학력 인증은 선택이다. 가치관은 만남 빈도와 연락 빈도를 필수로 하고 추가 문항은 추후 확정한다.

인증 상태는 미시작·진행 중·완료·실패·만료로 관리하고 실패 시 재시도, 만료 시 재인증을 제공한다. 사진은 미제출·검수 대기·승인·반려로 구분하며 24시간 이내 검수, 반려 사유와 재제출을 제공한다. 인증 원문은 공개하지 않고 배지만 표시한다.

## 하루 추천

한국 시간 오후 6시에 가치관 적합 후보 2명과 신규 가입 후보 1명을 함께 제공한다. 미오픈 카드는 이월하지 않으며 좋아요는 하루 최대 3회, 동일 상대 중복 전송 불가다. 후보가 부족하면 빈 카드나 중복 추천 대신 다음 코호트 일정을 안내한다.

자격 조건 적용 후 만남·연락 빈도, 생활 패턴, 흡연·음주, 지역·거리 선호를 비교한다. 관계 목적과 관심사는 확정 후 추가한다. 기술 스택은 보조 정보다. 가중치·신규 기간·노출 제외 기간·후보 부족 대체 기준은 추후 확정한다. 시·구 기반 거리 근사 방식을 사용하며 실시간 위치를 수집하지 않는다.

추천 설정은 최근 접속 24시간–10일, 거리 10–500km, 서울·경기 중복 선택, 나이 19–50세다. 카드에는 사진·직업·지역·인증 배지·가치관·생활 패턴·키워드를 우선 노출한다.

## 매칭과 채팅

상호 좋아요가 확인되면 즉시 매칭하고 매칭 상대끼리만 1:1 대화가 가능하다. 첫 질문은 ‘안녕하세요!’, ‘퇴근하셨나요?’ 및 공통 취향 질문이다. 자동 메시지는 없다. 개인 차단된 조합은 추천과 대화에서 제외한다. 신고는 운영 검토 이력과 유효 누적 횟수를 관리한다.

## 알림과 운영자

추천·매칭·메시지 알림은 카카오 알림톡을 우선 검토한다. 비즈니스 계정·제공사·비용·발송 동의는 연동 전에 확정한다. 문자 발송은 비용 확인 후 결정한다. 사진 검수 Discord 알림은 서버 연동 범위다.

운영 화면은 신규 가입·인증 상태, 사진 검수, 신고·차단, 역할·성별·가입 채널별 풀, 추천→좋아요→매칭→첫 메시지 퍼널을 제공한다. 실제 운영 시 관리자 인증과 감사 로그가 필요하다.

## 성공 지표

| 전환                             | 1차 기준 |
| -------------------------------- | -------- |
| 방문 → 온보딩 시작               | 30%      |
| 온보딩 시작 → 인증 완료          | 60%      |
| 추천 노출 → 좋아요               | 15%      |
| 좋아요 → 상호 매칭               | 15%      |
| 매칭 → 24시간 내 첫 메시지       | 60%      |
| 첫 메시지 → 5개 이상 메시지 교환 | 35%      |

2–4주 비교를 위한 기준선이다. landing_view, onboarding_start, verification_complete, photo_approved, recommendation_view, like_sent, match_created, first_message_sent, conversation_5_messages, report_submitted 이벤트를 제안한다. 역할·성별·채널·코호트·배지 유형을 분석 속성으로 기록하고 메시지 본문은 분석 이벤트에서 제외한다.

추천 노출은 실제 화면 노출 기준 사용자-상대-날짜별 중복 제거. 매칭 전환은 발송 좋아요 중 상호 전환된 비율. 5개 교환은 양쪽이 최소 1개씩 보낸 대화의 총 5개 이상으로 제안한다. 실험 전에 집계 기간과 정의를 고정한다.

## 베타 운영

같은 지역 개발자 60명·비개발자 60명을 대기 명단으로 확보한다. 30명씩 네 코호트를 구성하고 주 2회 동시 오픈한다. 성별·연령·상호 선호도 함께 고려한다. 2주 동안 전환과 역할별 이탈을 측정하고 인터뷰를 반영한다. 최소 유효 풀은 베타 데이터로 확인하며 부족한 코호트는 오픈을 미룬다.

## 이번 UI 구현

기존 다크 테마·코드 카드·하단 탭·최대 480px 모바일 화면을 유지한다. 기존 가입·추천·좋아요·매칭·채팅·프로필 경로에 하루 3명 안내, LGTM! 좋아요, GitHub 필수·회사 이메일 선택, 비개발자 개발자 추천, 만남·연락 빈도 입력, 한 화면에 2–3개씩 분리된 기본 프로필 입력, 추천 조건 UI, 모바일 운영자 검수 데모를 보완했다.

실제 카카오·GitHub·이메일 인증, 사진 업로드·검수, 추천 산정·오후 6시 배치·일별 초기화, 메시지 전송, 영구 차단, 알림, 분석, 관리자 권한은 미연동이다. 기본 프로필은 UI 체험이며 서버 저장·필수 검증은 후속 작업이다. 직군 필터만 고정 데모 카드에 적용되며 지역·나이·거리·접속 조건은 적용되지 않는다. 가입 완료 프로필은 localStorage, 좋아요·매칭·채팅은 sessionStorage에 보관하는 기존 구조다. 매칭은 민준 카드의 가상 상호 좋아요를 시연한다. 적합도·운영 수치는 예시다. 운영자 경로는 내 프로필의 ‘운영자 UI 체험’에서 접근한다.

## 제외

결제·구독·유료 가치관 필터, 휴대폰 본인 인증, 이메일 가입, 카카오 외 SNS 로그인, 자산·가족 심사, 커뮤니티, 채용·이직, 기술 블로그, GPS 탐색, 영상 통화, AI 자동 메시지, 오프라인 행사, 프리랜서 별도 심사, 매너 점수.

## 다음 단계

인증 정책·직무 검증 기준, 가치관 선택지·추천 가중치, 거리 계산, 부족 후보 정책, 신고 이의 신청, 개인정보 보관·삭제 정책 확정. 이후 인증 → 프로필·검수 → 추천 → 좋아요·매칭 → 채팅 → 알림 → 운영·분석 순서로 서버 연동한다.

## 모바일 가입 UX 보완

가입 순서는 역할 → 이름·나이·성별 → 지역·직업·학력 → 키·체형·종교 → 흡연·음주 → 사진·소개 → 인증 → 원하는 상대 → 만남·연락 빈도이다. 각 화면은 하나의 주제와 2–3개 입력으로 구성하며 이전 이동 시 값을 유지한다. 필수 항목을 입력하면 다음으로 이동할 수 있다. 사진은 파일 이름만 기억하며 실제 업로드하지 않는다.

기존 8개 O/X는 가입 완료 후 선택 질문으로 옮겼다. 직장·학교·키워드는 내 프로필에서 나중에 추가한다. 기존 인증·가치관·선호 수정 진입점은 유지한다. 실제 필수 검증과 개인정보 저장은 서버 연동 때 추가 검증한다.
